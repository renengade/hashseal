# 威胁模型

## 资产

- 交付文件的内容与文件名；
- Ed25519 私钥；
- `.sig`、`.tsr`、`MANIFEST.sha256`；
- 公钥指纹（信任锚）。

## 信任边界

```
私钥（A 独占）
   │ 签名
   ▼
文件 + .sig ──► TSA ──► .tsr
   │
   ▼
B：核对公钥指纹（独立渠道）→ verify
```

- **A 的私钥**：唯一能产生有效签名的东西；
- **公钥指纹**：B 必须通过独立渠道获得，否则中间人可同时替换公钥与签名；
- **TSA**：只证明“某时刻已存在”，不证明内容正确；其根证书是独立信任锚。

## 主要威胁与缓解

| 威胁 | 缓解 |
| --- | --- |
| 传输中被替换文件 | SHA-256 + Ed25519 签名 |
| 文件和哈希一起被替换 | 签名由私钥产生，攻击者无法伪造 |
| 目录中新增/删除文件 | 清单绑定完整集合，`verify DIR` 检测未列入与缺失 |
| 清单路径逃逸（`../`、绝对路径） | 解析时拒绝，解析后校验仍在根目录内 |
| 改名冒充 | 文件名纳入签名，默认拒绝改名；`--name` 显式放行 |
| 私钥泄露 | 口令加密、0600、KMS/HSM 建议；轮换与吊销仍待实现 |
| TSA 不可信/被攻破 | 多 TSA、证书 pin、离线验证；单一 TSA 是残余风险 |
| TSA 证书过期 | 按 `genTime` 验证；长期归档需 LTV/证据记录（未实现） |
| bundle 路径穿越 / zip-slip | 解包拒绝 `..`、绝对路径、符号链接条目 |
| 安装脚本被替换 | HTTPS、版本锁定、`HASHSEAL_SHA256`；发布签名仍待补 |
| 供应链依赖被替换 | `uv.lock` 锁定；SBOM 记录组件；in-toto/DSSE 证明 |
| 审计日志被本地篡改 | 默认本地文件可被同用户改动；合规场景应使用 syslog/SIEM 或只写存储 |

## 残余风险

- 签名者本人签了恶意内容：签名只证明“谁签的”；
- 私钥所在主机被完全控制；
- 本地审计日志不具备防 root 篡改能力；
- 单一 TSA 的可用性与可信度；
- 当前 SBOM 只到文件/依赖组件级，不含完整依赖树与许可证。

## 不在范围内

- 运行环境一致性（Python 版本、依赖行为）；
- 恶意软件检测；
- 私钥托管与硬件令牌（规划中）。
