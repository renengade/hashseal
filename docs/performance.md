# 性能

实测 256 MB 随机数据（单文件）：

| 操作 | 优化前 | 优化后 |
| --- | --- | --- |
| sign / verify 哈希 | ~0.3 s | ~0.3–0.5 s |
| bundle | **6.6 s**（deflate） | **1.9 s**（stored） |
| unpack | 2.6 s | **1.0 s** |

- bundle 默认**不压缩**（stored）：zip 仅作容器，GB 级交付物通常已压缩；
- 需要减小体积用 `--compress deflate`；
- 多文件目录可用 `-j N` 并行计算哈希。

## 大文件实测（2026-11，WSL2 / Ryzen 12 核，SHA-NI 生效）

`sha256_file` 读路径调优后（unbuffered + readinto 复用缓冲 + 32 MiB 块）：

| 场景 | 吞吐 | 1 GB 耗时 | 4 GB 耗时 |
| --- | --- | --- | --- |
| WSL ext4（本地盘） | ~2.5–3 GB/s | **≈ 0.7–1 s** | **≈ 3 s** |
| /mnt/d（9P → NTFS） | ~110 MB/s | ≈ 10 s | ≈ 40–50 s |

结论与建议：

- **本地盘上 GB 级哈希已经是秒级**（SHA-256 硬件加速生效，I/O 与哈希重叠）；
- 毫秒级不可能：任何哈希都必须把每个字节至少读一遍，这是物理下限；
- **`/mnt/*` 是瓶颈（9P 协议）**，代码无法突破；要快：
  - 把待签文件放进 WSL 本地目录（如 `~/sign-data`）再签名；
  - 或在 Windows 侧原生 Python 直接 `pip install hashseal`，对 `D:\` 原生读快 4–5 倍；
- 优化前的读法（8 MiB 块 + 双缓冲）在 256 MB 上慢约 10%，已在 v0.10.0+ 调优。
